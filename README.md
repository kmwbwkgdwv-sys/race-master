# race-master（レース・マスター）

スマートフォン横画面向けの3Dアクションレースゲームです。

- **`index.html`** … ブラウザでそのまま遊べる本体（WebGL、外部ライブラリなし）。
- **`admin.html`** … 管理者専用サイト（登録プレイヤーの一覧と対戦履歴）。
- **`firebase/database.rules.json`** … Firebase Realtime Database のルール。
- **`unity/`・`docs/`** … Unity 版に向けた設計書とコアスクリプト（未コンパイル。ブラウザ版とは別物で、今回の改良は入っていません）。

## ブラウザ版で遊べる内容

- **試合**：タイムアタック、VSレース（CPU 11台・3周・アイテム9種）、オンライン対戦（ルームID方式・最大12人、空き枠はCPU）
- **5コース**（1周 約40〜55秒。コースごとに長さが違う）。道幅を広げ、各コースに横道が3本（大きな近道2本＋1秒ほど縮まる小さな近道1本）
- **しかけ**：ジャンプ台、道を横切る動く障害物、グライダー区間のブーストリング、ダッシュパネル
- **グライダー**：滑空時間を長くし、飛行中はカメラが引いて着地先の道が見える
- **昼 / 夜**を試合前に選べる。コース選択に**ランダム**（開始時にルーレット）
- **キャラ**：30体。自分で絵を描いてスキンにできる。保存（16枚）・コード発行・コードで受け取り
- **カスタム**：ボディ・タイヤ・ウィング・エンジン（各4種）＋カラー12色＋グライダー4種。組み合わせを「マイセット」として8つまで保存し、いつでも（ルーム参加中でも）読み込める
- **車体ペイント**：お絵描き・画像貼り付け。保存（16枚）・コード発行・コードで受け取り
- **うしろボタン**：押している間だけ後ろを見る
- **ランキング**：アイテムなしのタイムアタックの最速ラップのみ。名前を押すとその記録の走りをリプレイで見られる
- **初回起動**：プレイヤー名 → 引き継ぎコードの発行と保存 → サーバー同期 → ゲーム開始（2回目以降は出ない）
- ドリフト＆3段階ミニターボ、救助ドローン、ボタン配置の変更、軽量化モード、BGM・効果音

### アイテム
- シールドはバリアが出ている間、重ねて使えません（効果は重複しません）。
- **ロケットブースト**（下位専用）：巨大ブースターを背負って10秒間の超加速＋無敵。

### オンライン対戦の仕組みと制限
- 自分のマシンは各端末で動かし、位置を約0.15秒ごとに Firebase へ送ります。CPUはホストの端末が動かします。
- 攻撃が当たったかどうかは撃った側の端末が判定します。通信の遅れにより、相手の位置は少しずれて見えます。
- ペイントとスキンは、同じルームの相手の画面にも表示されます（絵を `/paints/{uid}` に置き、ルーム内の更新番号 `pv` が変わると相手が読み直します）。大きすぎる絵は半分の解像度に縮めて送ります。
- ホストがルームを出るとルームは閉じます。アプリを閉じただけの場合、ルームのデータは Firebase に残ることがあります（コンソールから `rooms` を削除できます）。
- 通信部分（オンライン対戦・ランキング・リプレイ・スキンコード・管理者サイト）は**実際の Firebase では未テスト**です。うまく動かない場合はブラウザのコンソールのエラーを確認してください。

## GitHub Pages で公開する

1. このフォルダの中身をリポジトリのルートに置いて push。
2. GitHub の Settings → Pages → Branch を `main` / `(root)` にして保存。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます。管理者サイトは `…/admin.html` です。

## Firebase の準備

1. Firebase コンソール → Authentication → Sign-in method で **匿名** を有効にする。
2. Realtime Database → ルール に `firebase/database.rules.json` の中身を貼り付けて公開。
   **今回ルールが変わっています。必ず貼り直してください**（貼り直さないと、オンライン対戦の開始・リプレイ・スキンコード・対戦履歴・管理者サイトが動きません）。
3. 接続先は `index.html` と `admin.html` の `const FB = { key, db }` に書いてあります。

コースを作り直したため、ランキングは新しい場所（`rankings_v2`）に保存します。以前の記録（`rankings`）は表示されません。端末内のベストタイムも新しく数え直します。

### 管理者サイト（admin.html）の準備
1. Authentication → Sign-in method で **メール / パスワード** を有効にする。
2. Authentication → Users → 「ユーザーを追加」で管理者用のメールアドレスとパスワードを登録する。
3. `admin.html` を開いてそのアカウントでログインすると、画面に自分の **UID** が表示されます。
4. Realtime Database のデータ画面で `admins/{そのUID}` に `true` を入れる。
5. ページを開き直すと、登録プレイヤー（アイコンと名前）の一覧が出ます。プレイヤーを押すと、参加したマッチ・参加人数・順位・1周ごとのタイムが見られます。

`admins` に入っていないアカウントは、ログインできても一覧を読めません（ルールで拒否されます）。対戦履歴は、VSレースかオンライン対戦をゴールまで走ったときに記録されます。

## セットアップ

1. Unity（2022.3 LTS 以降、URP）で 3D プロジェクトを作成し、`unity/` 内を `Assets/Scripts/RaceMaster/` へコピー。
   - **Input System** パッケージを導入（Active Input Handling を Input System か Both に）。
   - `KartStats.cs` には ScriptableObject が4種入っています。Unity のバージョンによっては1クラス1ファイルに分ける必要があります。
   - `KartPaintEditor` の `paintShader` に `RaceMaster/PaintBlit` を割り当て、車体メッシュは Read/Write 有効＋MeshCollider 付きにします。
2. Firebase プロジェクトを作成し、**Authentication（匿名）** と **Realtime Database** を有効化。
3. Firebase Unity SDK から `FirebaseAuth` と `FirebaseDatabase` をインポートし、`google-services.json` / `GoogleService-Info.plist` を配置。
4. ルールをデプロイ：`firebase deploy --only database`
5. 起動シーンで `PlayerProfileService.BootAsync()` を呼び、戻り値（`FirstTimeRegistration` / `MainMenu`）で遷移先を決めます。

## Firebase データ構造

```
/codes/{sha256(引き継ぎコード)} = { playerId, uid }     … コードを知る端末だけが読める。uid が現在の持ち主
/secrets/{playerId}            = sha256(引き継ぎコード) … 書き込み1回のみ・読み取り不可（ルール内の所有者判定用）
/profiles/{playerId}           = { name, icon, updatedAt }   … 一覧で読めるのは管理者だけ
/rankings_v2/{stageId}/{playerId} = { name, icon, lapMs, achievedAt, mode }   … タイムアタックのみ
/replays/{stageId}/{playerId}  = { d, ms, kt, col, ch }  … ベストラップの走り（0.1秒ごとの位置を Base64 で）
/skins/{8文字のコード}          = { t: 'car'|'ch', n, d(画像), b, h, by, at }   … 書き込み1回のみ
/matches/{playerId}/{pushId}   = { at, stage, mode, n, hn, rank, laps, total, tod }   … 読めるのは管理者だけ
/paints/{uid}                  = { c(車体の絵), s(スキンの絵), h }   … オンライン対戦で相手に見せる絵。本人だけが書ける
/admins/{uid}                  = true                    … コンソールから手で入れる
/rooms/{roomId}                = { hostUid, maxPlayers, createdAt, stageId,
                                   players/{uid}: { name, icon, kt, col, pv, joinedAt, t },
                                   start: { stageId, aiCount, seed, order, tod, rnd, nonce },
                                   pos/{uid|aiN}, ev/{pushId} }
```

### ランキングの仕組み
- 記録は1人1ステージにつき自己ベスト1件。ルールで「持ち主のみ」「前より速いときだけ」「ステージごとの下限タイム以上」を強制。
- クライアントは `orderByChild("lapMs").limitToFirst(100)` を購読するため、誰かが更新すると全員の画面で自動的に並び替わります。
- ショートカット判定（全チェックポイント通過、正規ショートカットのみ省略可）は `LapValidator` がクライアント側で行います。

### プロフィールと引き継ぎ
- 初回登録時に 16 文字の引き継ぎコードを自動発行。端末（PlayerPrefs）とサーバーの両方に保存します。
- 名前・アイコンを変えると、`/profiles` と記録のある全ステージの `/rankings` 行を1回のマルチパス更新で同時に書き換えます。ランキングを開いている全端末に即時反映されます。
- プレイヤー名は表示名です（1〜12文字、日本語可、重複可）。同一人物かどうかは `playerId` で区別します。
- 別端末でコードを入力すると、その端末が新しい持ち主になり、旧端末からは書き込めなくなります。

### ペイントエディタの方式
- 車体メッシュのUV空間へのテクスチャブレンドです。ペイント層とステッカーを元テクスチャに重ねて `_BaseMap` に割り当てます。
- 端末のフォルダから画像を選ぶ画面はOSごとのピッカー（NativeGallery 等、WebGL は `<input type="file">`）が別途必要です。選ばれたパスまたはバイト列を `AddStickerFromFile` / `AddStickerFromBytes` に渡します。

## 既知の制限・今後の課題

- **不正対策**：ショートカット判定がクライアント側のため、改造クライアントからの不正記録は下限タイムでしか防げません。本番運用では Cloud Functions での検証に移すことを推奨します。
- **ルーム定員**：12人上限はクライアント側チェックです（ルールでは子要素数を数えられないため）。
- **レース中の同期**：Firebase はロビーと開始合図まで。走行中の位置同期は別途実装が必要です。
- **ボルケーノ・コアのニトロショートカット**：アイテムが出ないタイムアタックでは無効扱い（VSのラップのみ有効）にしています。
- **引き継ぎコードの扱い**：コードを知っている人は誰でもデータを引き継げます。他人に見せないよう画面で案内してください。
- **コイン・解放パーツ**：クライアントから書き込めるため改ざん可能です。課金要素にする場合はサーバー側検証が必要です。
- **スキンの共有**：オンライン対戦では相手の画面にも自分の絵が出ます。コードを伝えれば、相手も同じ絵を自分用に保存できます。
- **対戦履歴・リプレイ**：クライアントが送るデータなので、改造クライアントからは偽の内容を送れます。
- **ステッカーの歪み**：UV空間に貼るため、UVの継ぎ目をまたぐ位置では絵が切れます。車体のUV展開を大きな面でまとめておくと目立ちません。
- **未着手**：キャラクター30体、設定画面（軽量化モード・BGM/SE・レイアウト編集UI）。レイアウトの保存先 `ControlLayout` だけ用意済みです。
- **ランキング圏外の順位**：上位100件に入っていない場合の正確な順位表示は未対応です。
- ステージの下限タイム・チェックポイント番号は仮の値です。コース完成後に `LapTracker.cs` と `database.rules.json` の両方を合わせて調整してください。
